# Skillup interface system

## Internal surfaces: Operate

Use one sans family, the established blue accent, readable slate text, white work surfaces and quiet neutral navigation. A compact 26–30px heading identifies the task; one short sentence explains inputs or outcome. No eyebrow labels, promotional heroes, motivational sidebar cards, fake metrics, pastel card grids, nested cards, oversized pills or hover translations in workspaces.

## Task-specific structure

- Role selection: skill profile and ranked role list, with a structured comparison/details view.
- Shortlist review: resume/job evidence input and an explicit rule-based review with actionable findings.
- Project plans: editable schedules and real task completion.
- Experience drafting: user-supplied action, scope, tools and outcome; editable before/after output.
- Jobs: compact filters, deduplicated rows, selected-role details, saved state and pagination.
- Resume: full section editing and an accurate document preview; export uses the actual entered content.
- Interview: question navigation, answer workspace, practice timer, saved drafts and self-review.
- Companies: directory rows and factual profile sections, sourced/reference status near metadata.
- Overview: saved target, incomplete actions and recent work rather than a second landing page.

## Tokens

Accent #2549eb; foreground #182342; secondary #5f6d82; muted surface #f5f7fa; border #dfe5ee. Use semantic success/warning colors only for actual states. Body 14px, compact metadata 12px; do not shrink normal instructions below 12px. Spacing 4/8/12/16/24/32px. Container corners 8–12px, buttons 7–8px. Icons 18–20px without decorative backgrounds. Dense rows require sufficient hit area. Controls have explicit labels, focus states, loading, empty and error behavior.

## Quality gate

Every reachable page is reviewed for hierarchy, useful first viewport, distinct data, input/output relationship, meaningful controls, accessible labels, keyboard access and 390px layout. Reference data and heuristics must be named honestly. Do not certify a complete backend from successful UI interactions.
